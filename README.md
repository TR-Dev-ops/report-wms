# wms-realtime-report — Dashboard งานขาออกรายชั่วโมง

> สถานะ: **ระยะ 1 (ข้อมูลตัวอย่าง) เสร็จ / ระยะ 2 (ข้อมูลจริงจาก WMS) เจ้าของยืนยันแล้ว 2026-10-30** — เปิดใช้จริง ล็อกอินสำเร็จ และเทียบตัวเลขกับหน้า WMS ครบ 3 ช่วงเวลา ตรงทุกครั้ง — ผู้พัฒนา: Dev man | 2026-10-30
> อ้างอิง: บรีฟ (`brief.md`, ยืนยัน 2026-10-29) และดีไซน์ (`design/`, ยืนยัน 2026-10-30) — **เป็นเอกสารภายในที่เก็บไว้ในเครื่องเท่านั้น ไม่ขึ้น repo** (อยู่ใน .gitignore เพราะมีตัวเลขจริงจาก WMS และ IP ภายใน)

Dashboard หน้าเดียวสำหรับทีวี/คอม/มือถือ แสดงงานขาออกของวันนี้ (น้ำหนัก + จำนวนรถ), ยอดค้าง ณ ตอนนี้, สีแจ้งเตือนตามเกณฑ์, คาดการณ์เวลาเคลียร์งาน, กราฟรายชั่วโมง และตารางรายชั่วโมง
เปิดได้ 2 แบบ: `src\start.cmd` = **ข้อมูลสมมติ** (ระยะ 1) / `src\start-live.cmd` = **ข้อมูลจริงจาก WMS** (ระยะ 2 — ต้องตั้งค่า `.env` ก่อน ดูข้อ 8)

## 1. วิธีเปิดดู (ข้อมูลตัวอย่าง — โหมดข้อมูลจริงดูข้อ 8)

1. ดับเบิลคลิก **`src\start.cmd`**
2. หน้าต่างดำ (PowerShell) จะเปิดขึ้น และเบราว์เซอร์จะเปิด `http://localhost:8787/` ให้เอง
3. **เปิดหน้าต่างดำทิ้งไว้** ระหว่างดู — ปิดหน้าต่างนั้น (หรือกด Ctrl+C) เมื่อเลิกใช้

- ถ้าพอร์ต 8787 ถูกโปรแกรมอื่นใช้อยู่: เปิด PowerShell ในโฟลเดอร์ `src` แล้วรัน
  `powershell -ExecutionPolicy Bypass -File server.ps1 -Port 8788` แล้วเปิด `http://localhost:8788/`
- **อย่าดับเบิลคลิก `index.html` ตรง ๆ** — เบราว์เซอร์จะไม่ยอมให้หน้าอ่านไฟล์ข้อมูล หน้าจอจะขึ้นแถบแดงบอกให้ใช้ `start.cmd` แทน
- เปิดดูได้เฉพาะบนเครื่องนี้ (localhost) ทั้งสองโหมด — การเปิดให้คนอื่นในวงแลนดูยังไม่ทำ (ข้อ 8.9)

ปุ่มบนหน้าจอ: **ธีมสว่าง/ธีมมืด** (จำค่าที่เลือกไว้ในเบราว์เซอร์ ค่าเริ่มต้นมืด), **เต็มจอ** (สำหรับทีวี), ชี้เมาส์ที่กราฟเพื่อดูตัวเลข

### เหตุผลที่เลือกเทคโนโลยีนี้
- เครื่องนี้เป็น Windows **ไม่มี Python/Node** (ตรวจแล้ว: `python` เป็นแค่ตัวลิงก์ไป Microsoft Store, ไม่มี `node`) มี Windows PowerShell 5.1 และ Microsoft Edge
- หน้าจอ = **HTML/CSS/JS ล้วน** ไม่มีไลบรารี ไม่โหลดอะไรจากอินเทอร์เน็ต กราฟวาดด้วย SVG เอง
- เบราว์เซอร์ (Edge/Chrome) **บล็อก `fetch` จาก `file://`** จึงเลือก **เว็บเซิร์ฟเวอร์เล็ก ๆ ด้วย PowerShell** (`src/server.ps1`, ใช้ .NET `HttpListener` ที่มากับ Windows) แทนวิธีไฟล์ `data.js` เพราะ
  - หน้าจออ่าน **ไฟล์ JSON จริง** ตามที่ตกลง ระยะ 2 แค่เขียน `latest.json` ทับ ไม่ต้องผลิตไฟล์ 2 รูปแบบ
  - ระยะ 2 จะใช้ PowerShell ดึง WMS อยู่แล้ว ต่อยอดจากเครื่องมือตัวเดียวกันได้
  - ไม่ต้องติดตั้งอะไร และไม่ต้องใช้สิทธิ์ admin (ลงทะเบียนที่อยู่ `http://localhost:<พอร์ต>/`)
- `start.cmd` เรียก PowerShell ด้วย `-ExecutionPolicy Bypass` เฉพาะครั้งนั้น (ไม่เปลี่ยนค่าเครื่อง) เพราะ Windows ปิดการรันสคริปต์ .ps1 เป็นค่าเริ่มต้น
- เซิร์ฟเวอร์อ่านอย่างเดียวและ**ให้เฉพาะเครื่องนี้**: Windows (http.sys) รับการเชื่อมต่อทุกการ์ดแลนแม้ลงทะเบียนแค่ localhost จึงตรวจทุกคำขอ ถ้าไม่ได้มาจาก loopback (127.0.0.1 / ::1) ตอบ 403 ทันที; ตอบเฉพาะ GET/HEAD, ส่งได้เฉพาะไฟล์ในโฟลเดอร์ `src/web`, ไม่ส่งไฟล์หรือโฟลเดอร์ที่ชื่อขึ้นต้นด้วยจุด (เช่น `.env`, `.git/`), ส่ง `Cache-Control: no-store` เพื่อให้ได้ข้อมูลล่าสุดเสมอ

## 3. รูปแบบไฟล์ข้อมูล (JSON) — ตัวดึงระยะ 2 ผลิตรูปแบบนี้

ไฟล์เข้ารหัส UTF-8, ตัวเลขเป็น number (ไม่มีจุลภาคคั่นหลักพัน), หน่วยน้ำหนักเป็น **กก.** ตามหน้า WMS (หน้าจอแปลงเป็นตันเอง)

```json
{
  "schemaVersion": 1,
  "source": "wms",
  "note": "",
  "reportDate": "2026-10-30",
  "status": "ok",
  "message": "",
  "lastAttemptAt": "2026-10-30T16:55:04+07:00",
  "lastSuccessAt": "2026-10-30T16:55:04+07:00",
  "consecutiveFailures": 0,
  "rows": [
    { "period": "07:01-08:00", "workloadPct": 0, "weightKg": 0, "completeKg": 0, "remainingKg": 0, "completePct": 0,
      "truckCheckIn": 30, "truckOutbound": 0, "truckComplete": 0, "truckRemaining": 0, "truckCompletePct": 0 },
    "... ทั้งหมด 17 แถว 07:01-08:00 ถึง 23:01-24:00 เรียงตามเวลา ..."
  ],
  "total": { "workloadPct": 100, "weightKg": 0, "completeKg": 0, "remainingKg": 0, "completePct": 0,
             "truckCheckIn": 0, "truckOutbound": 0, "truckComplete": 0, "truckRemaining": 0, "truckCompletePct": 0 }
}
```

| ช่อง | ความหมาย |
|---|---|
| `schemaVersion` | ต้องเป็น `1` |
| `source` | `"sample"` = ข้อมูลตัวอย่าง (ขึ้นป้าย "ข้อมูลตัวอย่าง" และใช้ `sampleClock` ได้) / `"wms"` = ข้อมูลจริง |
| `reportDate` | วันที่ของรายงาน `YYYY-MM-DD` (แสดงที่แถบบนเป็น พ.ศ.) |
| `status` | ผลการดึง**รอบล่าสุด**: `ok` / `fetch_error` (ต่อ WMS ไม่ได้, timeout) / `login_failed` / `parse_error` (อ่านตารางไม่ได้ หน้าเว็บเปลี่ยน) |
| `message` | ข้อความสั้นอธิบายปัญหา (แสดงในแถบแดง) ห้ามมีรหัสผ่าน/URL |
| `lastAttemptAt` | เวลาที่ลองดึงครั้งล่าสุด (ISO 8601 มีโซนเวลา) |
| `lastSuccessAt` | เวลาที่ดึง**สำเร็จ**ครั้งล่าสุด = เวลาของตัวเลขใน `rows` (ใช้เป็น "อัปเดตล่าสุด", แถวชั่วโมงปัจจุบัน และจุดเริ่มคาดการณ์) |
| `consecutiveFailures` | จำนวนรอบที่ดึงไม่สำเร็จติดกัน (สำเร็จ = 0) |
| `rows` | 17 แถวตามหน้า WMS — `period` ต้องตรง `"HH:01-HH:00"` ทุกแถว ถ้าไม่ครบ/ผิดรูปแบบ หน้าจอจะซ่อนตัวเลขและแสดง "อ่านข้อมูล WMS ไม่ได้" |
| `total` | แถว Total ของ WMS (เก็บไว้ตรวจเทียบ) — **หน้าจอคำนวณผลรวมเองจาก `rows`** |

กติกาสำหรับตัวผลิตไฟล์ (ระยะ 2):
- ดึงสำเร็จ → เขียน `rows`/`total` ใหม่, `status: "ok"`, `consecutiveFailures: 0`, `lastSuccessAt = lastAttemptAt = ตอนนี้`
- ดึงไม่สำเร็จ / ล็อกอินไม่ผ่าน → **คง `rows`, `total`, `lastSuccessAt` เดิมไว้** แก้แค่ `status`, `message`, `lastAttemptAt`, `consecutiveFailures`
- อ่านตารางไม่ได้ → `status: "parse_error"` (หน้าจอซ่อนตัวเลขทั้งหมดไม่ว่า `rows` จะมีอะไร)
- เขียนไฟล์แบบปลอดภัย: เขียนลงไฟล์ชั่วคราวก่อน แล้วค่อยเปลี่ยนชื่อทับ `latest.json` เพื่อไม่ให้หน้าจออ่านเจอไฟล์ครึ่ง ๆ

## 4. ค่าตั้งค่า — `src/web/config.json`

แก้ด้วย Notepad แล้วบันทึก หน้าจอจะอ่านค่าใหม่เองในรอบถัดไป (หรือกด F5) — ช่องเกณฑ์ที่เป็น `null` หรือ `""` = **ยังไม่ได้ตั้ง → ไม่ใส่สี** (ค่าเริ่มต้นทุกช่องว่างตามบรีฟ ห้ามเดาตัวเลข)

| ช่อง | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `dataFile` | `"data/sample.json"` | ไฟล์ข้อมูลที่หน้าจออ่าน — ระยะ 2 เปลี่ยนเป็น `"data/latest.json"` (นี่คือสวิตช์ ข้อมูลตัวอย่าง/ข้อมูลจริง) |
| `refreshMinutes` | `5` | อ่านไฟล์ข้อมูลใหม่ทุกกี่นาที (ต่ำสุด 1 ตามบรีฟข้อ 9.5) และใช้คำนวณ "รอบถัดไป" / อายุข้อมูล |
| `staleGraceMinutes` | `2` | เวลาเผื่อให้ตัวดึงทำงานเสร็จ ก่อนนับว่าข้อมูลช้า (ค่าระบบ ไม่ใช่เกณฑ์ธุรกิจ) |
| `targetEndTime` | `""` | เวลาเลิกงานเป้า `"HH:MM"` เช่น `"20:00"` (รับถึง `"24:00"`) — ว่าง = การ์ดคาดการณ์ไม่ใส่สี |
| `forecastYellowWithinMinutes` | `null` | เหลืองเมื่อคาดว่าเสร็จก่อนเวลาเป้าไม่ถึง X นาที (เจ้าของยืนยัน 2026-10-30) — ว่าง = ไม่มีเหลือง มีแค่เขียว/แดง |
| `remainingTonsYellow` / `remainingTonsRed` | `null` | เกณฑ์ค้าง (ตัน) — ค้าง ≥ ค่านี้ = เหลือง / แดง |
| `remainingTrucksYellow` / `remainingTrucksRed` | `null` | เกณฑ์ค้าง (คัน) — ค้าง ≥ ค่านี้ = เหลือง / แดง |
| `sampleClock` | `"2026-10-30T16:56:00+07:00"` | เวลา "ตอนนี้" สมมติ ใช้**เฉพาะเมื่อไฟล์ข้อมูลเป็น `source: "sample"`** (ข้อมูลตัวอย่างมีเวลาตายตัว ถ้าใช้นาฬิกาจริงจะขึ้น "ข้อมูลเก่า" ทันที) — ขึ้นป้าย "เวลาจำลอง" บนหน้าจอ / ข้อมูลจริงใช้นาฬิกาเครื่องเสมอ / ว่าง = ใช้นาฬิกาเครื่อง |

กติกาสี: การ์ด "ค้าง" — ตั้งแค่เหลืองหรือแค่แดงก็ได้ ต่ำกว่าเกณฑ์ที่ตั้ง = เขียว; การ์ดคาดการณ์ — เวลาคาดการณ์ (แบบที่ช้ากว่าระหว่างน้ำหนักกับจำนวนรถ ข้อ 5) เลยเป้า = แดง, เหลือเวลาก่อนเป้าน้อยกว่า X นาที = เหลือง, นอกนั้นเขียว; คำนวณไม่ได้ = ไม่ใส่สี
ทุกสถานะมีไอคอน + ข้อความกำกับ ไม่ใช้สีอย่างเดียว

## 5. สูตรและกติกา

**ยอดค้าง ณ ตอนนี้** = `remainingKg` / `truckRemaining` ของ **แถวล่าสุดที่มีข้อมูล** (แถวที่มีช่องใดช่องหนึ่งไม่เป็น 0) — ไม่ใช้แถว 0 ของชั่วโมงที่ยังไม่ถึง
**ผลรวม** น้ำหนัก/เสร็จ/Check in/Outbound/รถเสร็จ = ผลรวมของ 17 แถว; % เสร็จ = เสร็จ ÷ รวม × 100 (รถ: เสร็จ ÷ Outbound)
**แถวชั่วโมงปัจจุบัน** = ช่วงชั่วโมงที่ `lastSuccessAt` ตกอยู่ (16:55 → 16:01–17:00); แถวหลังจากนั้นที่ไม่มีข้อมูลแสดงเป็น "–" สีจาง

**คาดการณ์ — 2 แบบเท่ากัน** (เจ้าของตัดสินใจ 2026-10-30: แสดงทั้งสองแบบขนาดเท่ากัน ยังไม่เลือกแบบหลัก เก็บประวัติไว้ฟันธงภายหลัง ดูข้อ 8.10)
สาเหตุที่ 2 แบบต่างกันได้มาก: น้ำหนักต่อคันของรถที่เสร็จแล้วกับรถที่ค้างไม่เท่ากัน (เช่น ที่เสร็จเฉลี่ย ~9 ตัน/คัน แต่ที่ค้าง ~18 ตัน/คัน) — หน้าจอจึงแสดง "ตัน/คัน เฉลี่ย" ไว้ใต้ทั้งคู่
**คาดการณ์เฉพาะงานที่เช็คอินแล้ว ยังไม่รวมรถที่จะเข้ามาเพิ่ม** (เขียนกำกับบนการ์ดด้วย)
```
เริ่มนับ    = ต้นชั่วโมงของแถวแรกที่มีงานเสร็จ (completeKg > 0 หรือ truckComplete > 0)   (แถว 09:01-10:00 -> 09:00)
ชม.ที่ผ่าน  = (เวลา lastSuccessAt - เริ่มนับ) ÷ 60            (ใช้ร่วมกันทั้ง 2 แบบ)
แบบน้ำหนัก : อัตรา = น้ำหนักเสร็จรวม (ตัน) ÷ ชม.ที่ผ่าน ; เวลาที่เหลือ = ยอดค้าง (ตัน) ÷ อัตรา
แบบจำนวนรถ: อัตรา = รถเสร็จรวม (คัน) ÷ ชม.ที่ผ่าน     ; เวลาที่เหลือ = รถค้าง (คัน) ÷ อัตรา
เวลาเคลียร์ = เวลา lastSuccessAt + เวลาที่เหลือ (ปัดเป็นนาที) ; เกิน 24:00 แสดง "หลัง 24:00"
ตัน/คัน เฉลี่ย: ที่เสร็จแล้ว = น้ำหนักเสร็จรวม (ตัน) ÷ รถเสร็จรวม ; ที่ค้าง = ยอดค้าง (ตัน) ÷ รถค้าง ; ตัวหารเป็น 0 -> "–"
สีเทียบเวลาเลิกงานเป้า: ใช้แบบที่เวลาเคลียร์ "ช้ากว่า" (กันประมาทเกิน) — แบบนั้นมีป้าย "ใช้ตัดสินสี" และบรรทัดเป้าเขียน "สีตาม: น้ำหนัก/จำนวนรถ (ช้ากว่า)"
แบบใดยังไม่มีงานเสร็จ -> "--:--" และ "ยังคำนวณไม่ได้" (ถ้าคำนวณได้แบบเดียว ใช้แบบนั้นตัดสินสี)
```

**สถานะการเชื่อมต่อ** (ตัดสินจากไฟล์ข้อมูล + อายุข้อมูล; I = `refreshMinutes`, g = `staleGraceMinutes`, อายุ = ตอนนี้ − `lastSuccessAt`)

| ลำดับตรวจ | เงื่อนไข | หน้าจอ |
|---|---|---|
| 1 | `status = "login_failed"` | แดง "ล็อกอิน WMS ไม่ผ่าน" + แถบแดง (โปรแกรมหยุดลองเอง) ตัวเลขเก่าเป็นสีเทาจาง |
| 2 | `status = "parse_error"` หรือไฟล์ผิดรูปแบบ | แดง "อ่านข้อมูล WMS ไม่ได้" + **ซ่อนตัวเลขทั้งหมด** |
| 3 | `consecutiveFailures ≥ 2` หรือ อายุ > 2I + g (ค่าเริ่มต้น > 12 นาที) | แดง "เชื่อมต่อ WMS ไม่ได้" + แถบแดง "ข้อมูลเก่า ณ …" ตัวเลขเทาจาง |
| 4 | `status = "fetch_error"` หรือ `consecutiveFailures = 1` หรือ อายุ > I + g (> 7 นาที) | เหลือง "ดึงข้อมูลไม่สำเร็จ 1 รอบ · กำลังลองใหม่" ตัวเลขยังแสดงปกติ |
| 5 | อื่น ๆ | เขียว "เชื่อมต่อ WMS ปกติ" |
| — | หน้าจออ่านไฟล์ข้อมูลไม่ได้เลย (ไม่มีไฟล์/เซิร์ฟเวอร์ปิด/เปิดจาก file://) | แดง "เปิดไฟล์ข้อมูลไม่ได้" ซ่อนตัวเลข — ถ้าเคยอ่านได้แล้วไฟล์หายไปทีหลัง จะคงตัวเลขเดิมและกลายเป็น "ข้อมูลเก่า" ตามอายุ |

หน้าจอประเมินอายุข้อมูลใหม่ทุก 30 วินาที และถ้าข้อมูลเริ่มช้าจะลองอ่านไฟล์ซ้ำก่อนรอบปกติ (ไม่ถี่กว่าทุก 60 วินาที) เพื่อไม่ให้ขึ้นเตือนผิดเพราะจังหวะรอบไม่ตรงกัน

**โหมดดูตัวอย่างสถานะ** (ปิดเป็นค่าเริ่มต้น): ต่อท้าย URL ด้วย `#preview=retry` / `stale` / `login` / `parse` / `ok` — จะขึ้นป้ายเส้นประ "จำลองสถานะ: …" ตลอดเวลา ลบท้าย URL ออกเพื่อกลับสู่สถานะจริง

## 7. ข้อจำกัดที่รู้
- โหมด `start.cmd` (ค่าเริ่มต้น): ตัวเลขทั้งหมดเป็นข้อมูลสมมติ และเวลา "ตอนนี้" มาจาก `sampleClock` — โหมด `start-live.cmd` ใช้ข้อมูลจริงจาก WMS และนาฬิกาเครื่อง
- เปิดดูได้เฉพาะเครื่องที่รัน `start.cmd` / `start-live.cmd` (localhost)
- ถ้าเซิร์ฟเวอร์ถูกปิดระหว่างที่หน้าเปิดค้าง หน้าจอจะคงตัวเลขเดิม แล้วขึ้น "ข้อมูลเก่า" เมื่ออายุเกินเกณฑ์ (ระยะ 1 ใช้ `sampleClock` ตายตัว จึงจะไม่ขึ้นเอง)
- จอ 16:9 ที่เตี้ยกว่า 1080 หรือตอนมีแถบแดง ตารางจะเลื่อนในกรอบของตัวเอง (ตามดีไซน์)
- เวลาแสดงตามนาฬิกา/โซนเวลาของเครื่องที่เปิดดู (เครื่องในบริษัทเป็นเวลาไทยอยู่แล้ว)
- เครื่อง Windows ต้องอนุญาตให้รัน PowerShell — ถ้าบริษัทล็อก PowerShell ด้วย Group Policy ต้องให้ IT ช่วย

ข้อจำกัดเพิ่มในระยะ 2:
- Parser ทดสอบกับ HTML จริงของหน้ารายงานผ่านแล้ว (2026-10-30) แต่ถ้า IT ปรับหน้าเว็บ อาจต้องปรับใหม่ — หน้าจอจะขึ้น "อ่านข้อมูล WMS ไม่ได้" ให้ทำตามข้อ 8.5
- ถ้า**ครั้งแรกที่รัน**ดึงไม่สำเร็จเลย (ยังไม่เคยมีข้อมูลสำเร็จ) หน้าจอจะขึ้น "อ่านข้อมูล WMS ไม่ได้" แทน "เชื่อมต่อ WMS ไม่ได้" เพราะยังไม่มีแถวข้อมูลให้แสดง — สาเหตุจริงอยู่ใน "รายละเอียด" ของแถบแดง (เช่น `เชื่อมต่อ WMS ไม่ได้ (ConnectFailure)`) และหายเองเมื่อดึงสำเร็จครั้งแรก
- รหัสผ่านอยู่ในไฟล์ `.env` เป็นข้อความธรรมดาบนเครื่องที่รัน (ป้องกันด้วยสิทธิ์ไฟล์ของ Windows เท่านั้น) และส่งผ่าน http แบบไม่เข้ารหัสเหมือนตอนล็อกอินด้วยเบราว์เซอร์ (บรีฟข้อ 9.3)
- ตัวดึงทำงานเฉพาะตอนที่หน้าต่าง "WMS fetcher" เปิดอยู่ ปิดหน้าต่าง = หยุดดึง (หน้าจอจะขึ้น "ข้อมูลเก่า" ตามอายุ)

## 8. ระยะ 2 — ข้อมูลจริงจาก WMS

> **แนะนำให้แจ้ง IT ก่อนเปิดใช้** ตามบรีฟข้อ 9.1 — โปรแกรมจะเข้า WMS ด้วยบัญชีของเจ้าของทุก 5 นาที (ประมาณวันละ 200 ครั้ง) และทุกครั้งจะถูกบันทึกในชื่อเจ้าของ

### 8.1 เจ้าของตั้งค่าครั้งแรก (Agent ไม่เห็นค่าเหล่านี้)
1. ในโฟลเดอร์โปรเจค คัดลอก `.env.example` แล้วตั้งชื่อใหม่เป็น `.env` (ไฟล์นี้อยู่ใน .gitignore ไม่ขึ้น repo)
2. เปิด `.env` ด้วย Notepad ใส่ 3 ค่าต่อท้าย `=` แล้วบันทึก:
   - `WMS_BASE_URL` = ที่อยู่ WMS ถึง `/wms` เช่น `http://<ที่อยู่เครื่อง WMS>/wms` (ดูจากแถบที่อยู่ในเบราว์เซอร์ ไม่ต้องมี `/` ท้าย)
   - `WMS_USERNAME`, `WMS_PASSWORD` = บัญชี WMS ของเจ้าของ (ไม่ต้องมีเครื่องหมายคำพูด)
3. (ทำแล้ว 2026-10-30) ยืนยัน parser กับหน้าจริงตามข้อ 8.5 — ทำซ้ำเฉพาะเมื่อหน้าเว็บ WMS เปลี่ยน

### 8.2 เปิดโหมดข้อมูลจริง
- ดับเบิลคลิก **`src\start-live.cmd`** → เปิด 2 หน้าต่าง: **"WMS fetcher"** (ตัวดึง) และหน้าต่างเว็บเซิร์ฟเวอร์ + เบราว์เซอร์ `http://localhost:8787/` — **เปิดทั้งสองหน้าต่างทิ้งไว้**
- สวิตช์ ข้อมูลตัวอย่าง/ข้อมูลจริง อยู่ที่ตัวเปิด ไม่ต้องแก้ไฟล์:
  - `start.cmd` = อ่านไฟล์ตาม `config.json` (ค่าเริ่มต้น `data/sample.json` = ข้อมูลตัวอย่างแบบระยะ 1)
  - `start-live.cmd` = เซิร์ฟเวอร์เปิดด้วย `-Live` ส่ง `config.json` ให้หน้าเว็บโดยเปลี่ยน `dataFile` เป็น `data/latest.json` และ `sampleClock` เป็นค่าว่าง (ใช้นาฬิกาจริง) **ไฟล์ `config.json` บนดิสก์ไม่ถูกแก้** ค่าอื่น (เกณฑ์สี, `refreshMinutes`) ใช้ร่วมกัน
  - (ทางเลือก) ถ้าอยากให้ `start.cmd` เปิดข้อมูลจริงด้วย ให้แก้ `config.json` เป็น `"dataFile": "data/latest.json"` และ `"sampleClock": ""` เอง
- ป้าย "ข้อมูลตัวอย่าง" และ "เวลาจำลอง" จะหายเองเพราะ `latest.json` เป็น `source: "wms"` (ทดสอบแล้ว)
- รันตัวดึงอย่างเดียว: `powershell -ExecutionPolicy Bypass -File src\fetch-wms.ps1` (วนตามรอบ) หรือเติม `-Once` (รอบเดียวแล้วจบ)

### 8.3 ตัวดึงทำงานอย่างไร (`src/fetch-wms.ps1`, PowerShell 5.1 ไม่ต้องติดตั้งเพิ่ม)
โครงหน้าล็อกอินที่ตรวจแล้ว (2026-10-30 เปิดดูแบบไม่ล็อกอิน): ฟอร์ม `POST <WMS_BASE_URL>/user/login` ช่อง `txtUserName` และ `txtPassword` **ไม่มี anti-forgery token**; ถ้ายังไม่ล็อกอินแล้วเปิดหน้ารายงาน WMS ตอบ `302` กลับไปหน้า `/User/Login`

ทุกรอบ (ทุก `refreshMinutes` จาก `config.json` อ่านใหม่ทุกรอบ ต่ำสุด 1 นาที):
1. ถ้ายังไม่มี session: เปิดหน้าล็อกอิน → ตรวจว่ามีช่อง `txtUserName`/`txtPassword` (ถ้าไม่มี = หน้าเปลี่ยน → `parse_error` **ไม่ส่งรหัสผ่าน**) → ส่งชื่อผู้ใช้/รหัสผ่าน **1 ครั้ง**
2. เปิดหน้า `<WMS_BASE_URL>/Report/ReportShipmentSumByProduct` ด้วย session เดิม (cookie อยู่ในหน่วยความจำเท่านั้น)
3. อ่านตารางใต้หัวข้อ "Outbound the amount of work each day" แล้วตรวจก่อนเขียน — ข้อใดไม่ผ่าน = `parse_error` ไม่เขียนตัวเลข:
   - หัวคอลัมน์ตรงลำดับ Period / Workload / Outbound (Weight, Complete, Remaining, Complete %) / Truck (Check in, Outbound, Complete, Remaining, Complete %)
   - มี 17 แถว `07:01-08:00` … `23:01-24:00` ตามลำดับ + แถว Total 1 แถว, ทุกแถว 11 คอลัมน์, ทุกช่องเป็นตัวเลข (ตัด `,` และ " น." ออก)
   - ผลรวมน้ำหนัก/เสร็จ ตรงกับ Total (คลาดได้ ≤ 0.01 กก.) และผลรวมรถ Check in/Outbound/Complete ตรงกับ Total พอดี
   - ยอดค้างสะสมต่อเนื่อง: ค้างแถวนี้ = ค้างก่อนหน้า + เข้า − เสร็จ (ข้ามแถวที่ไม่มีความเคลื่อนไหวและค้างเป็น 0 = ชั่วโมงที่ยังไม่ถึง) และค้างในแถว Total = ค้างแถวล่าสุด
4. เขียน `src/web/data/latest.json` ตามรูปแบบข้อ 3 (เขียน `latest.json.tmp` ก่อนแล้วเปลี่ยนชื่อทับ)

ไม่ follow redirect เอง และเรียกแค่ 2 ที่อยู่ข้างบน (อ่านอย่างเดียว ไม่กดอะไรอื่นใน WMS) — log อยู่ที่ `logs/fetch-YYYY-MM-DD.log` (อยู่ใน .gitignore) บันทึกแค่เวลา, รหัส HTTP, สถานะ และยอดรวม **ไม่บันทึกรหัสผ่าน, cookie, ที่อยู่ WMS หรือ HTML**

### 8.4 สถานะที่ตัวดึงเขียน และสิ่งที่ต้องทำ
| สถานะ | เกิดเมื่อ | ตัวดึงทำอะไร | หน้าจอ | คนต้องทำ |
|---|---|---|---|---|
| `ok` | อ่านตารางผ่านทุกข้อ | เขียนตัวเลขใหม่, `consecutiveFailures` = 0 | เขียว | — |
| `fetch_error` | ต่อ WMS ไม่ได้, timeout, WMS ตอบ 5xx | คงตัวเลขเดิม + `lastSuccessAt` เดิม, `consecutiveFailures` +1, **ลองใหม่รอบถัดไป** | 1 รอบ = เหลือง, ≥ 2 รอบ = แดง "ข้อมูลเก่า" | ถ้าแดงนาน: ตรวจแลน/เครื่อง WMS |
| `login_failed` | WMS ไม่รับรหัส, หรือ session หมดอายุแล้วล็อกอินใหม่ 1 ครั้งไม่ผ่าน, หรือไม่มี/ค่าไม่ครบใน `.env` | เขียนสถานะแล้ว **หยุดทันที ไม่ลองซ้ำ** (กันบัญชีถูกล็อก) | แดง กุญแจ ตัวเลขเก่าเทาจาง | แก้ `.env` แล้ว **บันทึก** แล้วเปิด `start-live.cmd` ใหม่ |
| `parse_error` | หน้าล็อกอิน/หน้ารายงานเปลี่ยน, หาตารางไม่เจอ, คอลัมน์/แถวไม่ตรง, ผลรวมไม่ตรง, หน้ารายงานตอบ 4xx | ไม่เขียนตัวเลขใหม่, ลองใหม่รอบถัดไป (ไม่เสี่ยงบัญชี) | แดง ซ่อนตัวเลขทั้งหมด | แจ้งผู้ดูแลโปรแกรม พร้อมบันทึกหน้ารายงานใส่ `samples/` (ข้อ 8.5) |

**กันลองล็อกอินซ้ำ:** ถ้ารอบก่อนจบด้วย `login_failed` แล้วมีคนเปิดตัวดึงใหม่โดย **ยังไม่ได้แก้/บันทึก `.env`** ตัวดึงจะไม่ล็อกอินและปิดตัวเอง (ไม่ส่งคำขอใด ๆ) — ถ้ารหัสถูกอยู่แล้ว (เช่น IT ปลดล็อกบัญชีให้) รัน `powershell -ExecutionPolicy Bypass -File src\fetch-wms.ps1 -ResetLogin` 1 ครั้ง

### 8.5 ยืนยัน parser กับหน้าจริง (ทำแล้ว 2026-10-30 — เก็บขั้นตอนไว้ใช้เมื่อหน้าเว็บ WMS เปลี่ยน)
Parser ทดสอบกับหน้ารายงานจริงที่เจ้าของบันทึกไว้ใน `samples/` ผ่านแล้ว (ตารางอยู่ใน HTML ที่เซิร์ฟเวอร์ส่งมา; หัวข้อ `<h4>` อยู่ในตาราง layout และตารางข้อมูลอยู่ถัดไป) — ถ้าวันหนึ่งขึ้น `parse_error` เพราะหน้าเว็บเปลี่ยน ให้เจ้าของบันทึกหน้าใหม่ไว้ทดสอบตามขั้นตอนนี้ (Agent ล็อกอินไม่ได้):

   - ใช้ Ctrl+U ไม่ใช่ "บันทึกหน้าเว็บ" ธรรมดา เพราะต้องการ HTML ที่เซิร์ฟเวอร์ส่งมาจริง (ถ้าตารางถูกเติมด้วย JavaScript ภายหลัง ซอร์สจะไม่มีตาราง ตัวดึงก็จะไม่เห็นเหมือนกัน)

2. รัน `powershell -ExecutionPolicy Bypass -File src\fetch-wms.ps1 -HtmlFile samples\report-<วันที่>.html`

### 8.10 ประวัติการดึง (ไว้วิเคราะห์ว่าการคาดการณ์แบบไหนแม่นกว่า)
- **ที่อยู่:** `logs/history-YYYY-MM-DD.local.jsonl` (1 ไฟล์ต่อวันตามนาฬิกาเครื่องที่รันตัวดึง) — **เป็นข้อมูลจริง** อยู่ใน .gitignore (`logs/` และ `*.local.jsonl`) ห้ามคัดลอกออกนอกเครื่อง
- **เขียนเมื่อไร:** ทุกครั้งที่ดึงสำเร็จ (`status: ok`) ต่อท้าย 1 บรรทัด หลังจากเขียน `latest.json` เสร็จแล้ว — ดึงพลาดไม่เขียน; ถ้าเขียน history ไม่ได้ (ดิสก์เต็ม/ไฟล์ถูกล็อก) จะบันทึกใน log แล้วทำงานต่อ `latest.json` ไม่กระทบ
- **รูปแบบ:** JSON Lines (1 บรรทัด = 1 JSON object), UTF-8, ไม่มีที่อยู่ WMS/cookie/ชื่อผู้ใช้/รหัสผ่าน
  ```
  {"fetchedAt":"2026-10-30T10:35:04+07:00","reportDate":"2026-10-30",
   "total":{ ...ช่องเดียวกับ total ใน latest.json... },
   "rows":[ ...17 แถว ช่องเดียวกับ rows ใน latest.json... ]}
  ```
  (ตัวอย่างนี้แสดงหลายบรรทัดเพื่อให้อ่านง่าย ในไฟล์จริงอยู่บรรทัดเดียว) — ขนาดประมาณ 3 KB ต่อบรรทัด ≈ 0.6 MB ต่อวันที่รอบ 5 นาที
- **วิธีวิเคราะห์ (ทำภายหลังเมื่อเก็บได้หลายวัน):**
  1. แต่ละบรรทัด คำนวณการคาดการณ์ทั้ง 2 แบบด้วยสูตรข้อ 5 (`dataMin` = เวลาใน `fetchedAt`, ผลรวมจาก `rows`) → ได้ "เวลาที่คาด (น้ำหนัก)" และ "เวลาที่คาด (รถ)" ของบรรทัดนั้น พร้อม "รถค้าง ณ ตอนนั้น" = `truckRemaining` ของแถวล่าสุดที่มีข้อมูล
  2. หา**เวลาที่เคลียร์งานกลุ่มนั้นได้จริง**: ไล่บรรทัดถัด ๆ ไปของวันเดียวกัน หาบรรทัดแรกที่ `truck Complete` สะสม (ผลรวม `truckComplete` ของ `rows`) ≥ รถเสร็จสะสม ณ ตอนคาดการณ์ + รถค้าง ณ ตอนคาดการณ์ — เวลาใน `fetchedAt` ของบรรทัดนั้น คือเวลาที่รถกลุ่มที่เช็คอินแล้วตอนนั้นเสร็จครบ (ไม่นับรถที่เข้ามาเพิ่มทีหลัง ซึ่งตรงกับขอบเขตของการคาดการณ์) ทำแบบเดียวกันด้วยน้ำหนัก (`completeKg` สะสม ≥ เสร็จสะสม + ยอดค้าง ณ ตอนนั้น) เพื่อเทียบอีกมุม
  3. ความคลาดเคลื่อน = เวลาที่คาด − เวลาที่เสร็จจริง (นาที) ของแต่ละแบบ → เทียบค่าเฉลี่ยของค่าสัมบูรณ์ และดูว่าแบบไหนมักคาดเร็วเกิน (อันตรายกว่า) แยกตามช่วงเวลาของวัน (เช้า/บ่าย/เย็น)
  4. ถ้าวันนั้นรถกลุ่มนั้นยังไม่เสร็จก่อนบรรทัดสุดท้ายของวัน ให้ตัดออก (ไม่รู้เวลาเสร็จจริง)
  - ใช้ Excel เปิดได้ด้วย Power Query (Get Data → From File → JSON/Text แล้วแยกแต่ละบรรทัดเป็น JSON) หรือให้นักวิเคราะห์ข้อมูลทำ
  - ข้อควรระวัง: ข้อ 2 ใช้หลัก "เสร็จก่อน-มาก่อน" (FIFO) โดยประมาณ ถ้ารถที่เข้ามาทีหลังถูกโหลดก่อน เวลาจริงจะเร็วกว่าความจริงของกลุ่มเดิมเล็กน้อย
